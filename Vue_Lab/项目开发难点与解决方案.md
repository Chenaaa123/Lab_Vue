# 校园实验室预约系统 - 项目开发难点与解决方案

## 一、项目开发难点概述

在校园实验室预约系统的开发过程中，遇到了多个技术难点和挑战。这些难点主要集中在权限控制、数据一致性、性能优化、安全防护等方面。本文档详细记录了这些难点、具体的Bug表现以及相应的解决方案。

## 二、核心技术难点

### 2.1 权限控制复杂性

#### 遇到的难点：
- **问题描述**：4种用户角色的权限交叉和继承关系复杂
- **具体表现**：
  - 实验室管理员只能管理自己负责的实验室
  - 系统管理员拥有所有权限
  - 前端菜单需要根据角色动态显示
  - API接口需要细粒度权限控制
  - 权限配置需要支持动态调整

#### 解决方案：

**后端权限控制：**
```java
// 自定义权限注解
@Target({ElementType.METHOD})
@Retention(RetentionPolicy.RUNTIME)
public @interface RequirePermission {
    String value();
    String labManager() default "";
}

// AOP切面实现权限验证
@Aspect
@Component
public class PermissionAspect {
    @Around("@annotation(requirePermission)")
    public Object checkPermission(ProceedingJoinPoint joinPoint, RequirePermission requirePermission) {
        // 获取当前用户信息
        UserDetails currentUser = SecurityContextHolder.getContext().getAuthentication().getPrincipal();
        String userRole = currentUser.getRole();
        Long userId = currentUser.getUserId();
        
        // 检查基础权限
        if (!hasPermission(userRole, requirePermission.value())) {
            throw new AccessDeniedException("权限不足");
        }
        
        // 实验室管理员特殊处理
        if ("LAB_MANAGER".equals(userRole) && !StringUtils.isEmpty(requirePermission.labManager())) {
            Long labId = extractLabId(joinPoint.getArgs());
            if (!isManagerOfLab(userId, labId)) {
                throw new AccessDeniedException("您不是该实验室的管理员");
            }
        }
        
        return joinPoint.proceed();
    }
}
```

**前端权限控制：**
```javascript
// 路由守卫实现
router.beforeEach((to, from, next) => {
```

### 2.2 预约时间冲突检测

#### 遇到的难点：
- **问题描述**：并发预约时的时间冲突检测
- **具体表现**：
  - 两个用户同时预约同一时间段
  - 数据库并发写入导致冲突
  - 前端状态更新不及时
  - 边界时间处理复杂

#### 解决方案：

**数据库层冲突检测：**
```sql
-- 时间冲突检测SQL
SELECT COUNT(*) as conflict_count 
FROM reservations 
WHERE lab_id = ? 
AND status IN ('PENDING', 'APPROVED')
AND (
    (start_time <= ? AND end_time > ?) 
    OR (start_time < ? AND end_time >= ?)
    OR (start_time >= ? AND end_time <= ?)
)
AND id != ?  -- 排除当前编辑的预约
```

**后端乐观锁实现：**
```java
@Service
@Transactional
public class ReservationService {
    
    @Retryable(value = {OptimisticLockingFailureException.class}, maxAttempts = 3)
    public Reservation createReservation(Reservation reservation) {
        // 检查时间冲突
        if (hasTimeConflict(reservation)) {
            throw new BusinessException("该时间段已被预约，请选择其他时间");
        }
        
        // 设置版本号实现乐观锁
        reservation.setVersion(1);
        reservation.setStatus(ReservationStatus.PENDING);
        
        return reservationRepository.save(reservation);
    }
    
    private boolean hasTimeConflict(Reservation reservation) {
        int conflictCount = reservationRepository.countTimeConflict(
            reservation.getLab().getId(),
            reservation.getStartTime(),
            reservation.getEndTime(),
            reservation.getId()
        );
        return conflictCount > 0;
    }
}
```

**前端实时冲突检测：**

### 2.3 前后端数据一致性

#### 遇到的难点：
- **问题描述**：前端状态与后端数据不同步
- **具体表现**：
  - 预约状态变更后前端显示不及时
  - 多个页面同时修改同一数据
  - 网络异常导致状态丢失
  - 缓存数据与数据库不一致

#### 解决方案：

**Vuex状态管理优化：**
```javascript
const store = createStore({
  state: {
    reservations: [],
    labs: [],
    lastUpdateTime: null,
    syncStatus: 'IDLE' // IDLE, SYNCING, ERROR
  },
  
  mutations: {
    UPDATE_RESERVATION(state, reservation) {
      const index = state.reservations.findIndex(r => r.id === reservation.id)
      if (index !== -1) {
        state.reservations.splice(index, 1, reservation)
      }
      state.lastUpdateTime = new Date().toISOString()
    },
    
    SET_SYNC_STATUS(state, status) {
      state.syncStatus = status
    },
    
    MERGE_RESERVATIONS(state, newReservations) {
      // 合并数据，避免重复
      const existingIds = new Set(state.reservations.map(r => r.id))
      const uniqueNewReservations = newReservations.filter(r => !existingIds.has(r.id))
      state.reservations.push(...uniqueNewReservations)
    }
  },
  
  actions: {
    async syncReservation({ commit }, reservationId) {
      commit('SET_SYNC_STATUS', 'SYNCING')
      try {
        const response = await api.getReservation(reservationId)
        commit('UPDATE_RESERVATION', response.data)
        commit('SET_SYNC_STATUS', 'IDLE')
      } catch (error) {
        commit('SET_SYNC_STATUS', 'ERROR')
        throw error
      }
    },
    
    async refreshReservations({ commit, state }) {
      if (state.syncStatus === 'SYNCING') return
      
      commit('SET_SYNC_STATUS', 'SYNCING')
      try {
        const response = await api.getReservations({
          lastUpdateTime: state.lastUpdateTime
        })
        commit('MERGE_RESERVATIONS', response.data)
        commit('SET_SYNC_STATUS', 'IDLE')
      } catch (error) {
        commit('SET_SYNC_STATUS', 'ERROR')
      }
    }
  }
})
```

## 三、常见Bug及修复

### 3.1 状态管理Bug

#### Bug描述：
```javascript
// Bug：状态更新不生效
// 问题代码：
const updateReservation = (reservation) => {
  state.reservations.push(reservation)  // 直接修改state
}

// 修复：使用mutation
const mutations = {
  ADD_RESERVATION(state, reservation) {
    state.reservations.push(reservation)
  }
}
```

#### 根本原因：
- 直接修改state违反了Vuex的状态变更规则
- Vue无法检测到直接数组修改
- 缺少响应式更新机制

### 3.2 异步处理Bug

#### Bug描述：
```javascript
// Bug：异步操作顺序问题
// 问题代码：
const submitForm = async () => {
  validateForm()  // 没有await，异步验证未完成
  const result = await submitData()  // 可能在验证未完成时提交
}

// 修复：正确处理异步
const submitForm = async () => {
  try {
    await validateForm()  // 等待验证完成
    const result = await submitData()
    ElMessage.success('提交成功')
  } catch (error) {
    ElMessage.error('提交失败：' + error.message)
  }
}
```

#### 根本原因：
- 异步函数调用时缺少await关键字
- 错误处理不完整
- 没有考虑异步操作的时序问题

### 3.3 内存泄漏Bug

#### Bug描述：
```javascript
// Bug：组件销毁时未清理事件监听
// 问题代码：
onMounted(() => {
  window.addEventListener('resize', handleResize)
  timer = setInterval(updateData, 5000)
})

// 修复：清理副作用
onUnmounted(() => {
  window.removeEventListener('resize', handleResize)
  if (timer) {
    clearInterval(timer)
  }
})
```

#### 根本原因：
- 组件销毁时未清理事件监听器
- 定时器未正确清理
- 内存中累积了无用的引用
